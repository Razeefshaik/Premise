# ADR-007: Deduplicate Paylane webhooks at ingress

## Context
Paylane delivers payment confirmations as webhooks and retries a delivery until we acknowledge it.
Retries can arrive hours later, so the same confirmation may reach us several times.

## Decision
webhookingress records each event_id in the shared Redis cluster and drops any webhook whose event_id
it has already seen. Records live for the dedupe window, which must cover Paylane's whole retry window.
webhookingress acknowledges every webhook immediately, before forwarding it to paymentservice.

## Consequences
Downstream services see each confirmation once, as long as Paylane's retry window stays inside our dedupe window.
